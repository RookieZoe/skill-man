# Domain docs

Read this guidance when exploring or changing product behavior, architecture, or domain terminology.

- This is a single-context repository. Read relevant sections of [CONTEXT.md](../../CONTEXT.md) and the [ADRs](../adr/README.md) that touch the task; do not load unrelated decisions.
- Use the glossary's domain terms in code, tests, issues, and proposals. If a needed concept is missing, flag the terminology gap rather than silently inventing a synonym.
- If a proposal contradicts an applicable ADR, name the conflicting decision and explain the proposed change instead of silently overriding it.
- For distribution state copy and compatibility rules, read [Distribution](distribution.md).

Do not create missing domain documents preemptively; add them when a task resolves an actual terminology or decision gap.
